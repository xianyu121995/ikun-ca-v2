# 定稿 UI 与冻结业务契约的接入差异

这些是后续领域批次的待审阅事项，不是本轮新增API或业务开发许可。保留用户定稿，不通过静默截断、伪造数据或重写业务消除差异。phase2-v1.0.0仍为当前业务协议；需要扩展时另做明确版本修订和验收。

| 领域 | 定稿UI提出的差异 | 后续门槛 |
|---|---|---|
| 主页/Projects | 独立重要事件名、日期和小时；已有token_date仅日精度 | B2审阅独立事件字段与时区、未知值、00/23时排序；不得把事件小时塞进token_date或猜精确时间 |
| 主页/Projects | 北京日期组合筛选与全量排序；演示最多100个已加载记录 | B2审阅服务器查询边界和cursor，不能用前端分页伪装全量查询 |
| 主页/Projects | 完成后移出主页、保存原进度、完成记录和恢复 | B2审阅一个授权操作的原子性/revision/幂等/审计；恢复真实原进度，不操作监控，不物理删项目 |
| Hunter | V3 token计划、profile bio、关注标记与公开DTO并非完全一一对应；演示id非canonical | B4最小投影与必要的契约修订；hidden注册/人工confirmed/真实command状态保留，不能根据界面推断启动成功 |
| Hunter | 管理页面仅统计及用户名操作，不列个体账号 | B4继续禁止普通DTO/日志/SSE泄露猎手身份；UI固定布局，不为后端便利重新暴露名单 |
| Tracking | Account/Post/ui_key展示模型与subscription/project分离ID；重要标记、互动数、媒体未在原DTO中 | B3确认来源可提供什么；未知不补0或演示值，订阅及canonical身份由服务端解析，X用户名不自动变项目ID |
| Tracking | 定稿仅S/A/B展示、备注优先、六条分页；live管理目前只读 | B3明确其他评级的展示/过滤和权限适配；不修改评级本体，不把demo添加/删除回调用于生产 |
| 公共组合 | 各页面原公共包pin不同；统一视觉在全站review组合层 | B0/C0审阅固定UI包和样式组合的正式收件方式，继续使用一个AppShell；不复制第二套组件，不在本轮合入页面 |

本轮实际产出仅基础设施与本地UI验收。Auth密码表单P0和最终权限回归仍在原冻结候选，尚未修复；B1–B4继续held。
