# ikun.ca UI 设计规范 v1

状态：公共 UI 候选，基础提交 `f89d8f55fc3e68d6360e7a1e33e23bde48591098`；工作分支 `codex/website`。已读取总管 AGENTS、HANDOFF、GIT、OWNERSHIP、ARCHITECTURE、API、DEPLOYMENT。本文不包含三个业务页面、认证或监控实现。

## 视觉原则

面向长时间查看信息、筛选表格和核对来源的专业交易终端。界面使用冷灰底色、细边框和小圆角；主操作用青绿色；盈利、失败、风险与连接状态使用各自的语义色。禁止用大片渐变、发光装饰和过多卡片挤占数据空间。颜色不能代替文字状态。

## 导航和宽屏布局

全站仅三个业务入口：主页 `/`、猎手监控 `/hunter`、猎手项目监控 `/tracking`。这是本 UI 候选提交的页面路由建议，需总管统一到三个业务窗口；基础 API 文档尚未约定页面路径。账号管理 `/account` 属于导航底部的账号区域，不增加第四个业务入口。登录建议 `/login`。组件不会创建这些路由。当前入口通过精确路径或完整路径段匹配，主页不能对所有 URL 处于激活状态。

桌面侧栏 216px，主区域可收缩（min-width:0），内容内边距 24px。主内容充分利用 1440/1920/2560px 宽屏。页面标题在上方；其后筛选与搜索；然后主要数据；次级说明在底部。业务窗口负责数据结构、列选择与领域操作。

小于 1180px 时侧栏缩为图标轨道并保留可访问名称；小于 768px 时导航变成顶部三入口，表格在自己的区域横向滚动。不得让整个页面因表格变宽而横向溢出。

## 交互和状态

每个操作具有实际回调或明确禁用及原因。主按钮每个操作组最多一个。破坏性操作必须由业务确认弹窗提交，默认焦点放在取消。异步提交 pending 时禁用重复提交，保留按钮文字并显示进度。浏览器重试与资金、付费研究等副作用由业务控制，公共 UI 不自动重试。

首次加载展示结构骨架并提供 aria-busy；后台刷新保留已有数据，显示“更新中”；空数据与筛选无结果区分。错误提供可读标题、下一步、可选请求编号与显式重试。部分加载失败不能清空已成功数据。断线显示最近更新时间和“连接中断”，恢复后由业务状态更新。禁止通过进程存在或 HTTP 200 推断监控连接正常。

搜索必须有标签，Esc 清除、清除按钮只在有值时显示；UI 层保持受控输入，debounce/AbortController 属于业务数据层。排序通过表头按钮和 aria-sort 表示，公共组件只回传排序意图，消费者负责服务端或当前完整数据集排序；不能将当前页排序伪装成全量排序。表格使用原生 table 语义，行的主要动作使用独立链接/按钮；选中与悬停不能仅靠颜色表达。分页遵循 API 的 opaque cursor，不添加页码 checkpoint。

弹窗使用原生 dialog 的模态行为，打开后焦点进入弹窗，Tab 限于弹窗，Esc 可关闭（pending 时阻止关闭），关闭后焦点回到触发元素。初始焦点可用 initialFocusRef 指定，破坏性操作指定取消按钮。背景点击默认不关闭。未保存修改由业务在 onOpenChange 回调中提供关闭确认。禁止嵌套模态弹窗。

成功通知 5 秒后关闭；错误保留至用户关闭；关键错误同时保留在内容区域。组件不展示堆栈、SQL、密钥或原始服务响应。尊重 prefers-reduced-motion，禁用闪烁与不必要动画。所有控件具有可见 focus-visible 状态。

## 评分

评分组件接受业务传入的 grade 与可选 value，不推算项目级别。S/A/B/C/D 与未知具有文字标签与独立色阶；未知显示“未评分”，不可显示为 0 或成功。value 仅接受业务已归一到 0–100 的有限数值，异常数值不显示；有效 grade 可以独立显示。分数与等级不匹配时由业务处理，不在 UI 中重算。评分说明与方法、时间由业务在详情面板提供。

## 登录和账号管理

登录使用同一深色底与 420px 表单面板，包含品牌、账号、密码、提交、就地错误和明确的会话状态说明。密码支持可访问的显示/隐藏切换，支持浏览器自动填充，不限制粘贴。认证失败措辞由认证层传入，组件不自行区分用户存在与否。展示组件不存储密码或 token。

账号管理沿用 AppShell / PageHeader / Panel / Input / DataTable：个人资料、权限与安全信息分区。以最新 HANDOFF 为准，真实权限只有 superadmin / user，所有业务写入只允许 superadmin，user 只读，不开放公开注册。roleLabel 仅是展示文字；公共包不据此授权，服务端必须重新校验。退出、重置或删除动作由认证窗口提供回调；无能力时明确禁用。认证展示不能被解释为认证后端已完成。

## 模块边界

packages/ui 只拥有 React 展示组件、CSS tokens、设计文档和本地组件预览。禁止导入监控脚本、数据库驱动、后台服务或密钥；禁止实现轮询、SSE、Watch 订阅和业务存储。三个业务窗口各自拥有页面、请求层和状态。根依赖 / lockfile / 根布局修改由项目总管集成。

## 业务错误呈现

| API code / 状态 | 展示与动作 |
| --- | --- |
| AUTH_NOT_CONFIGURED / NOT_IMPLEMENTED | “功能尚未接入”，禁用相关提交；不展示空成功 |
| UNAUTHENTICATED / 会话失效 | 由认证窗口重新认证；保留安全的筛选状态，不缓存凭据 |
| FORBIDDEN | “当前账号无操作权限”；不自动重试 |
| VERSION_CONFLICT / IDEMPOTENCY_CONFLICT | 保留本地编辑，提示读取最新版本并人工确认；不覆盖 |
| RATE_LIMITED | 显示业务层计算的 Retry-After，按钮等待到期；不在组件内部计费重试 |
| UPSTREAM_UNAVAILABLE / DB_UNAVAILABLE | 显示最近更新时间与 request_id；仅在业务允许时提供显式重试 |
| unknown / 无回执 | “结果待核实”；禁用重复写入，先由业务查询回执 |

Alert 的 message、requestId 必须由调用方通过公开 DTO 白名单传入，不可直接展示原始异常或原始 Hunter payload。

## 验收矩阵与依据

桌面：1440×1000、1920×1000、2560×1000；紧凑：1024×1000；窄屏：390×1000。检查整页宽度、表格内部滚动、导航可访问名称、键盘焦点、搜索清除、排序、错误保留数据、模态焦点恢复及登录/账号未接入状态。具体本次证据见 HANDOFF.md。

输入遵循 [React 官方 input 文档](https://react.dev/reference/react-dom/components/input)；模态交互参考 [W3C Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)；数据表格参考 [W3C Table Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/table/)。这些语义和对比度检查不等于完整 WCAG 认证或真实辅助设备验证。
